# 一轮精读的样子

这是基于[原创虚构材料](../evals/fixtures/windowed-retrieval.md)手工编写的展示示例，不是一次模型运行日志，也不报告真实科研结果。实际运行结果另见评估记录。

## 在第一轮教学之前

讲解者先完整阅读源文件，包括方法、公式、表格、结论、两个附录和参考说明。它应当已经知道：

- 主要问题有“有用证据通常在局部窗口内”的前提。
- 普通测试中 0.90 与 0.92 是单次训练得到的数值，不能据此断言统计等效。
- 长度64且证据通常在窗口外时，窗口模型下降到0.58。
- 候选配对数量不等于实际时间或设备峰值内存。
- 附录A限制了新模板泛化结论，附录B限制了数值复现。

这些结论用于保证第一段解释不失真，不需要全部塞进第一段。准备未完成时不能先展示下面的教学内容，再回头补读。

语义计划按原文顺序组织为：摘要的范围主张；问题与分布假设；窗口机制、公式及符号；成本口径；评估条件与结果表；结论和外推限制；附录的划分与复现边界。标题、声明、参考说明另作已核查的支持材料登记。

## 第一次教学回复

**位置：摘要全文。这个小段说明作者研究什么，以及主张适用于什么范围。**

**原文**

> We study a windowed retrieval model for a synthetic sequence task. On the fixed-length benchmark, the windowed model attains accuracy close to a dense model while evaluating fewer token pairs. We investigate the conditions under which this comparison remains useful.

**翻译**

我们研究了一种用于合成序列任务的窗口式检索模型。在固定长度的基准测试中，该模型在评估更少词元对的同时，取得了接近稠密模型的准确率。我们考察了这种比较在哪些条件下仍然有意义。

**理解**

这段有三个连续动作：提出研究对象，给出一个有条件的结果，再表明要检查它的适用条件。

“窗口式”意味着只在某个局部范围内查找信息；“稠密”模型在这项任务中可以访问所有更早位置。现在先理解这两个查找范围的区别，窗口的具体定义将在方法部分读到。

第二句有两个不能忽略的限定：结果来自固定长度的基准；减少的是被评估的词元对数。因此这里不能改写成“窗口模型在所有序列上都一样准确且运行更快”。原文后面的实验和附录会进一步解释这个边界。

这不是让我们立刻判断哪种模型更好，而是提出一个要沿着全文核对的问题：当查找范围缩小，哪些信息还能被找到，哪些信息可能丢失？

**首次体验后的选项**

后续可以保持当前方式，也可以调整提问、背景知识深度、公式推导和每轮篇幅。你希望保持当前方式，还是调整其中某一项？

## 用户选择之后

用户：“保留提问，公式细一点；每次一小段。”

后续行为：保持关键节点提问、公式包含逐步推导、每轮一个单元。记录本次选择，直接进入下一未讲单元，不再询问同一组选项。

用户：“这一题先不答，继续。”

后续行为：正常推进；如果下一段需要该知识，可以用一句简短解释衔接。不能强迫用户答题，不能把跳过算成答对或答错。

用户：“这一段少讲点基础。”

后续行为：只调整当前单元，之后恢复已有深度；如果用户说“以后都少讲基础”，才更新会话持续偏好。

用户：“后面不要提问。”

后续行为：持续关闭主动理解题，保留用户自然插问的空间，不重复确认。上述选择均不改变完整研读、准确对应原文和保持证据边界这些基础要求。
