# 根据全文逻辑设计教学单元

仅在完成全文研读、建立主张—证据关系后执行本规范。论文的源段落是定位单位，教学单元是理解单位，两者不必一一对应。

## 选择分段点

优先寻找论证功能的变化：背景转研究缺口、问题转设计、定义转推导、方法转验证、结果转解释、结论转限制。每个单元围绕一个主要问题，但不得为了凑“一问”拆散必要信息。

一个好的单元应满足：

1. **意义完整**：读者知道这一块提出、解释或证明了什么。
2. **条件完整**：主张和它的假设、限定、指标口径保持关联。
3. **上下文足够**：指代、符号和必要前置概念能够被找到。
4. **负担适中**：围绕一个主要理解障碍，篇幅由内容决定，而非固定句数或字数。
5. **可追溯**：准确映射回原文，合并、拆分和调整都有理由。

不要把“每三句一组”“每页一课”或“每段都单独教”作为通用规则。

## 可以拆与不宜拆的情况

| 情况 | 处理 |
| --- | --- |
| 一个长段先介绍问题，再讲独立方案和实验 | 在功能转换处拆开，标为同一原文段的不同部分 |
| 相邻短段共同定义一个概念 | 合成一个教学单元，保留各段边界与位置 |
| 论点下一句给出必要限定 | 一起讲，或在当前单元显式保留限定；不能把限定推迟到用户可能读不到的地方 |
| 公式定义跨页，下一段才给符号含义 | 同一单元收齐定义；不要让用户对未定义符号猜测 |
| 图分为多面板，后续面板构成对照 | 先建立整图关系，再按问题分讲，不展示局部后假装全图支持结论 |
| 主文声称提升，附录揭示评价条件变化 | 在结果第一次被解释时交代相关条件，并给出附录定位 |
| 证明有多个依赖步骤 | 分成定义、关键步骤和结论，但每步保留所需假设和前置命题 |
| 多个重复实验使用相同方法 | 允许围绕差异合讲，但逐项映射来源与结果，不悄悄漏过反例 |

## 保持原文顺序与依赖关系

默认依原文顺序推进，让用户能够同步阅读 PDF。全文理解使讲解者知道后文信息，但不应因此随意重排成另一篇教程。

遇到后文才解释的概念，选择最小干预：

- 当前理解只需要一句定义：补一句并标明后文会详细展开。
- 当前结论的边界依赖后文：当下说明这个边界及来源，不能等读到后文才修正误导。
- 大量背景会打断主线：记为待回访，读到相应位置再展开。
- 确需调整顺序才能理解：说明调整原因、原文位置与返回点；不删除原有覆盖关系。

“暂存到后文”只适用于非阻断的教学背景，不适用于讲解者尚未读过或尚未理解的核心内容。

## 分段计划最少记录什么

每个教学单元至少记录：

- 稳定编号，例如 `U03`；修订时尽量保留已有编号。
- 一句话主题或核心问题。
- 原文位置，以及包含的源单元和必要上下文。
- 拆分、合并或调整的理由。
- 前置概念与必要依赖。
- 图表、公式、脚注和附录的去向。
- 当前状态：计划、已讲、用户跳过或待回访；用户跳过不等于已讲。

所有实质性内容必须有去向。作者机构、致谢、参考文献列表等可以作为已读的支持材料，不要求逐条翻译教学，但需明确其处理方式。若用户要求全文逐段对照，则这些部分也按约定纳入交付；不要用“教学重点”替代用户要求的完整覆盖。

把每个源单元分配给一个主要去向；跨单元复用时用上下文引用标记。检查重复讲解、遗漏和未解决的前置依赖。

## 全文计划与用户体验

第一课前需要有全篇分段方案，但不必把长表全部展示给用户。通常只展示当前位置和当前单元目标；用户需要时再展示阅读路线。

用户觉得太细时，合并尚未讲过、逻辑相连的单元；觉得太快时，拆开后续单元并补回必要概念。调整的是交付颗粒度，不是全文阅读要求，也不是事实和边界。

变化后核对覆盖关系和进度。例如 `U04` 拆为 `U04a`、`U04b`，应保留原来的来源映射；不能把父单元“已讲”自动传播给尚未讲解的子单元。

## 检验分段质量

进入教学前，抽查最容易误导的边界，而不是只检查标题格式：

- 摘要的结论是否带入后文已经明确的关键条件？
- 方法的公式与符号、参数与训练设置是否被分开后失去联系？
- 实验图表的指标口径、开发集和测试集是否被混淆？
- 相互矛盾或不支持主张的结果是否仍有明确去向？
- 附录中改变理解的材料是否被用于设计分段？
- 用户按计划读完，能否重建研究问题、方法、证据及边界？
