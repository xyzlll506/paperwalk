# 固定基础与可选教学方式

开始第一教学单元前读取。偏好只控制呈现与互动，不改变完整阅读、准确翻译、来源定位或证据边界要求。

## 选项与默认值

| 选项 | 可选值 | 默认行为 |
| --- | --- | --- |
| 设置入口 | `before_first_unit` / `after_first_unit` / `provided` | 未指定时先完成全文准备，示范一单元，再问一次是否调整；已有偏好记为 `provided` |
| 提问 | `off` / `checkpoints` / `dialogue` | `checkpoints`：只在重要概念、推导或小节结束时提问 |
| 讲解深度 | `foundational` / `standard` / `advanced` | `standard`：先精炼解释，关键新概念适度展开 |
| 公式 | `intuition` / `derivation` / `both` | `both`：直觉加当前理解必需的推导 |
| 例子 | `examples: true` / `false` | `true`：有实际帮助时给例子；需要完整算例时可直接提出 |
| 每轮份量 | `one_unit` / `several_units` | `one_unit`：每轮一个意思完整的教学单元 |
| 复盘 | `recaps: true` / `false` | `true`：小节结束时简短整理逻辑；关闭后仍可按用户请求复盘 |
| 导出 | 不自动导出 / 用户按需请求 | 不自动创建持久笔记或文件；请求落盘时另记具体范围和位置 |

这些是内部可记录的值，与 [会话状态](session-state.md) 一致，不要求把配置代码给用户。自然语言选择与这些值等效。不要为每个选项都单独问一次，也不需要用户逐项填表。更细的例子风格、临时偏好和导出请求可以在扩展字段中记录，不更改基础状态的含义。

`advanced` 允许省略用户已掌握的基础解释，不允许删掉作者的条件。`intuition` 不免除准确展示、阅读和核查公式；如果完整推导对结论不可替代，说明原因并给最少必要步骤。

## 两个设置入口

**已有偏好时直接采用。** 例如用户说“原文配翻译，公式详细推导，不提问”，不需要重新询问。已有会话偏好在续读时保留。

**用户希望先设置时**，开始准备后用简短问题收集最关键的选择，同时继续不依赖答案的材料研读。不要让可选设置阻塞全文阅读。

**没有偏好时**，完成全文准备及分段后，以默认方式展示一个真正的教学单元，再用一次简短的校准邀请：

> 后面可以保持这个方式，也可以调整：是否保留提问、基础知识解释的多少、公式推导深度，以及每次阅读的份量。直接告诉我想改哪一项即可。

这是一种示例，不要求逐字照抄。只问最可能改善当前体验的几项，不把内部选项全集变成长问卷。如果用户说“继续”或没有选择，按当前方式推进，不重复追问。样例教学不得在全文准备完成之前进行。

## 每个单元怎样讲

先给准确定位与本块主题，然后依次呈现原文、译文和独立解释。原文过长需要拆分时明确标为同一段的几部分；不在原文中混入讲解。

译文保留：数值、符号、比较对象、条件、否定、因果方向与不确定语气。并列或同时发生不能擅自译成因果，例如 “while evaluating fewer pairs” 应表达“在评估更少配对的同时”，不能凭此断言“因为减少配对所以提高性能”。术语第一次出现给出中英对应，后续一致。原文歧义可以解释，但不得用翻译偷偷修正文中的科学错误。

解释聚焦当前最重要的理解障碍：

1. 这段实际上在说什么？
2. 它为什么放在这里，与前后文如何衔接？
3. 哪个术语、设计选择、推导或证据需要补充才能理解？

不需要每次把这三个问题写成标题。已经讲懂的术语直接使用；不要为凑完整模板重复讲解。

例子优先沿用同一场景，从文字逐步走到数据、公式或机制。明确标注演示数字、假设场景和示意图，不把教学例子说成论文的实验结果。比喻达到边界时说明，逐渐用真实计算或证据替换比喻。

用户选择的例子、代码或推导应服务于理解；不要在未请求时把带读扩成复现实验、软件项目或文献综述。

## 提问的三种方式

### `off`：不主动测验

持续讲解，允许用户随时插问。不要在结尾换一种说法继续出题。必要的来源澄清或材料缺失问题不属于教学测验，仍可提出。

### `checkpoints`：关键节点检查

只在会改变后续理解的重要节点提一个问题。例如解释假设、预测移除某模块的后果、判断实验能否支持某结论、手算一个小步骤。

背景段无需自动配题。二选一可以用于建立初步区分，但不要把明显答案的选择题当成深度理解证明。提问后给用户回答的机会，不立即自问自答；用户要求直接解释或说“继续”时，正常推进。

### `dialogue`：对话式推进

更频繁地使用复述、预测、推导和举例，但仍一次一个核心问题。根据回答决定提示、补充解释或推进，不按预设问卷机械执行。

答错时指出具体误解，给最小必要提示；仍不清楚时直接解释。不要无限提示、反复考试或要求答对才能继续。用户表达疲劳或不希望回答时，立即减轻互动。

所有方式都不得以一次答对宣称“已经掌握”。只有与当前问题相关的障碍才记录，避免给用户贴永久能力标签。

## 偏好更新与局部插问

- “这一段详细讲”“这个公式只讲直觉”：只作用于当前内容。
- “以后都少问一点”“接下来每次讲两段”：更新后续偏好。
- 模糊要求先作最小的局部调整；如果长期效果很重要，再简短确认。
- “继续”：保留现有偏好，推进下一单元，无需先完成问题。
- 插问之后说明返回点，继续当前单元或下一单元，不丢失进度。
- 来源、版本或研究范围改变时更新准备记录；偏好设置本身不要求重新阅读全文。

## 复盘与收尾

小节复盘重建概念关系，不再逐字重复刚才的解释；可用简短图示、例子或结构化问题，但遵守提问开关。

区分三个事实：讲解者是否完整研读、已经向用户讲了哪些单元、用户在哪些地方表示理解或仍有疑问。三者不能互相替代。

教学结束时说明覆盖及用户主动跳过的内容，并按偏好回顾研究问题—方法—证据—边界。导出文件、生成学习计划、安排复习或开展研究扩展都需要用户选择或请求；不要把它们附加为默认流程。
